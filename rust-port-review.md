**Findings, ordered by impact**

1. **[P1] Query noise at reception completion, not PHY ingress.** The [shared PHY](/home/joe/src/sleepybishop/emane/rust/emane-core/src/nem_manager.rs:4916) calculates the noise floor immediately and puts the scalar in `RxProperties`. `reception_noise_floor_dbm` passes a future EOR timestamp to the monitor, but this cannot include transmissions that have not arrived yet. [Wi-Fi caches this scalar](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:2635) and reuses it when `complete_receive` evaluates PCR. TDMA evaluates PCR immediately as well. C++ Wi-Fi requests the spectrum window inside its EOR callback (`maclayer.cc:596–671`); TDMA requests it at slot-end processing (`receivemanager.cc:179–232`). A probe using the actual Rust monitor and a copy of the exact PHY helper measured **−100 dBm at ingress versus −60 dBm at EOR** when an out-of-band interferer began halfway through the packet. The current MAC uses the stale −100 dBm value. This is a shared architectural issue: MACs need a way to query the completed spectrum interval while preserving TDMA's ingress-time slot checks. Simply delaying the entire PHY callback would interfere with those checks.

2. **[P1] Restore C++ TDMA payload-capacity and airtime accounting.** [Rust subtracts 144 bytes before taking any data](/home/joe/src/sleepybishop/emane/rust/plugins/tdma/src/lib.rs:1512), plus 64 bytes for each previous aggregated component. C++ `basemodelimpl.cc:1067–1092` passes the full `(slot duration − overhead) × rate / 8` capacity to the queue; `queue.cc:147–174` charges component payload bytes. A **1 ms slot, 100 µs overhead and 1 Mbit/s rate** has capacity for 112 bytes in C++; Rust cannot dequeue even a 100-byte packet because the reserve consumes the entire slot. Repeated slots cannot drain the queue. Separately, [Rust computes airtime from serialization plus 64 bytes](/home/joe/src/sleepybishop/emane/rust/plugins/tdma/src/lib.rs:1478), whereas C++ uses dequeued component bytes. A 100-byte component at 1 Mbit/s is **800 µs in C++ versus 1,456 µs in the Rust probe**. Restore the original modeled-byte contract for fidelity, or explicitly document this as a model change. The new reserve test proves that the reserve covers serialization overhead; it does not prove compatibility with C++.

3. **[P1] Preserve TDMA's per-slot receive lock and earliest-SOR selection.** [Rust uses the pending delivery queue as a receive lock](/home/joe/src/sleepybishop/emane/rust/plugins/tdma/src/lib.rs:2053), then [releases deliveries at EOR](/home/joe/src/sleepybishop/emane/rust/plugins/tdma/src/lib.rs:2222). C++ `ReceiveManager::enqueue` retains one candidate per absolute slot and replaces it if another packet has an earlier modeled start of reception; the candidate is processed at slot end. The isolated Rust callback probe delivered **two frames from the same slot**, after completing the first EOR callback and then admitting the second. Rust also cannot replace a pending later-SOR candidate with an earlier one, and incomplete fragments do not occupy `pending_rx` at all. Reception arbitration needs its own per-slot state, independent of completed packet delivery/reassembly state. Wi-Fi's different receive model should not inherit this lock.

4. **[P1] Allow the stock C++ Wi-Fi PCR document's DOCTYPE.** [Wi-Fi calls `Document::parse`](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/pcr_manager.rs:49), which rejects DTD declarations by default. The actual C++ `ieee80211pcr.xml.in` begins with `<!DOCTYPE pcr SYSTEM ...>`. Loading it through the current Rust PCR manager fails with **`Failed to parse XML: XML with DTD detected`**; `start` consequently fails. This is the same class of compatibility problem already repaired for antenna XML in `5e1e248`. Use the corresponding parser option and test a fixture containing the declaration, rather than only the stripped guide fixture.

5. **[P2] Carry the originating data duration in Wi-Fi CTS announcements.** [Rust calls `cts_duration(mode, rate_index)`](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:1587) when sending the CTS. C++ `handleUpstreamPacket` copies the received RTS/CTS-data duration into the CTS entry (`maclayer.cc:776`); `sendDownstreamUnicastCts` preserves it in the wire header (`maclayer.cc:1295–1305`). This duration tells other nodes about the originating hidden transmission and feeds two-hop utilization. For a received duration of **2,000 µs at rate index 12/mode 1**, Rust advertised **23 µs**. The CTS path needs the received data duration passed through explicitly. Comparing only connectivity misses the resulting hidden-terminal/contention error.

6. **[P2] Sample collision noise using the C++ neighbor distribution.** [Rust replaces random neighbor selection with one packet-weighted mean power](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:1293). C++ `checkUpstremReception` invokes `getRandomRxPowerCommonNodesMilliWatts` / `getRandomRxPowerHiddenNodesMilliWatts`; those select a neighbor using utilization-derived probability intervals and return that neighbor's mean power. With two possible interferers at **1 mW and 0.001 mW**, Rust always returned **0.5005 mW**, which is neither possible C++ sampled value. PCR is nonlinear, so applying it to the average noise does not preserve the acceptance probability. Restore the selection distribution and exercise asymmetric-power common and hidden neighbors.

7. **[P2] Preserve the conditional subtraction in Wi-Fi pre-transmit delay.** [Rust uses `saturating_sub(overhead)`](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:1224). C++ `MACLayer::setDelayTime` subtracts only when the accumulated pre-delay is strictly greater than the overhead; otherwise it leaves that delay intact (`maclayer.cc:1491–1505`). Saturation instead erases the delay when overhead is larger or equal. A deterministic ten-neighbor, short-message probe produced **34 µs in Rust versus 44 µs using the C++ rule**. This changes the pre/post delay split and transmission timing under load. Mirror the conditional and cover both sides and equality.

8. **[P2] Sample Wi-Fi queue metrics when packets leave the queue.** The [enqueue-side update](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:2452) always supplies delay `0`; there is no corresponding update in `send_downstream`. C++ samples queue depth, discarded packets since the last sample, and `currentTime − acquireTime` in `sendDownstreamMessage` (`maclayer.cc:1347–1353`). The Rust transmit probe with a packet held for at least 10 ms produced **no queue-metric sample**. Thus average queue delay remains zero even during congestion. In addition, `queue_discards` is cumulative and never cleared, so a past drop can be reported again after metric intervals reset. Restore dequeue/transmit sampling and interval discard semantics before adding TDMA-style diagnostic counters.

9. **[P2] Commit the fixture required by the new Wi-Fi test.** [The test added in `5e1e248`](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/pcr_manager.rs:27) unconditionally loads `validation/guide-samples/ieee80211abg-pcr.xml`. `git ls-files validation` returns no files; the entire directory is currently untracked. The suite passes here because that local file exists, but the branch alone cannot satisfy the test. Running the copied test outside this checkout reproduced **`No such file or directory (os error 2)`**. Put the fixture under a tracked test-fixture directory or embed the needed document.

10. **[P3] Match C++ Wi-Fi time conversion where exact timing fidelity matters.** [Rust rounds packet duration upward](/home/joe/src/sleepybishop/emane/rust/plugins/ieee80211abg/src/lib.rs:845); C++ converts positive `DoubleSeconds` to integer microseconds with `duration_cast`, truncating each duration. The probe for a 1,500-byte unicast at 54 Mbit/s in mode 1 produced **286 µs versus 285 µs**. Propagation added to the slot time also rounds up in Rust, versus truncation in C++. RTS/CTS duration terms are separately truncated in C++, so reproducing the combined formula alone is insufficient. This is smaller than the modeling defects above, but the existing `timing_matches_legacy_rate_table` test never asserts a numeric legacy airtime.
